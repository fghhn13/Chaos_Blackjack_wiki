文档将该框架标为已实现，现已进入游戏主线。目标是在保留共用中央牌局区的同时，让不同荷官展示各自机制。

## 界面增加什么

每张牌桌选择左右侧栏的部件顺序。放不下的部件提示玩家到局内面板查看。Tab 打开面板，Escape 或 Tab 关闭，左右键或标签快捷键切换。信息通常只读，组件也可提供明确的操作入口。

道具以快捷槽展示，玩家回合可点击或用 1～9 使用；Bag 标签替代旧道具场景。侧栏消息流展示近期事件和错误，完整局内日志最多保留 400 行并随存档保存；旧行被丢弃后，累计计数仍继续。

默认布局（经典桌和无模式 `--chaos`）使用共用荷官、规则、消息流、牌堆、道具槽和按钮，面板含 Bag、Rules、Log、Run。扑克头构筑桌额外显示状态与牌桌动作，并加入 Build、Finance 标签，这些部件只读取其公开快照。J-54 的部件只读取它的公开快照：按热度上色、点击即可切掉对应组的牌堆条，带下注档位的胜率仪表，徽章（算力、条件、预告、小丑、固件、悬赏），以及可点击的操作徽章；这张牌桌不卖东西，因此没有道具槽，Deck 标签里是仪表和完整热度表。热度条可以设置色深、单独的提示和动作，进度条也可以带刻度。

## 如何扩展新牌桌

机制层提供状态与动作。注册部件将状态转成精简或完整视图，使用统计、标记、条形图、进度、列表、行、槽位、日志等数据组件；共用渲染器负责绘制，布局决定侧栏位置和面板标签。动作描述经控制器执行，包括使用道具、购买、回答选择和牌桌自有动作。动作是否可用来自 Agent 读取的同一份动作列表（见[道具架构](design-item-architecture.html)）；每个道具槽注明何时可用及不可用原因。需要提问的命令打开统一的选择界面，它只发送选择或取消。

荷官与牌堆交互可打开相应面板、固定检查信息或显示台词；点击消息流标题打开完整日志。GUI 组件不改变 Agent 的观察协议。新增牌桌提供机制、部件与布局即可，无须重写共用牌局场景。
